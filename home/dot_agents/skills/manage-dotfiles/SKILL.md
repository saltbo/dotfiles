# Dotfile maintenance

The chezmoi source repository is the only place a managed file is changed. The files in the home directory are copies that chezmoi renders from it, so an edit made there never reaches the repository, and the next apply overwrites it. Every change moves one way: source, pull request, merge, apply. Run Git operations through `chezmoi git`.

## What to track

- Track personal configuration worth preserving to rebuild the environment, including global agent instructions and user-maintained skills.
- Exclude credentials, private keys, sessions, history, caches, logs, tool databases, and other runtime state. Exclude temporary experiments as well.
- The repository is public. Preserve machine differences and personal values such as email addresses with templates, conditions, or an unmanaged local include, and supply secrets through encryption or secret references.
- Leave a file the owning tool rewrites, such as one generated by `rtk init`, out of chezmoi and manage it through that tool.

## Make a change

1. Start from the source repository on `main`, in sync with the remote and with a clean `chezmoi status`. Reconcile any drift first, as described below, so the change does not carry unrelated differences.
2. Create a branch for the change.
3. Change managed files with `chezmoi edit <file>`, or by editing the source file directly when working noninteractively. Add a new file by creating it where it is used and importing it with `chezmoi add <file>`. Keep existing templates, symlinks, and machine-specific handling, and never replace a template source with its rendered output.
4. Review the change with `chezmoi diff` and the Git diff, select only this task's files, commit, push, and open a pull request.
5. Merge the pull request, then switch the source repository back to `main`, pull, and delete the branch locally and on the remote. A squash merge leaves the branch's commits unmerged in Git's eyes, so a branch kept around looks diverged later.
6. Run `chezmoi apply` and check the result in the real configuration.

The change is done when it is merged, applied, the branch is gone, and `chezmoi status` is empty.

## Reconcile drift

A file in `chezmoi status` differs between source and home. Either the home copy was changed outside chezmoi, often by an application or installer writing to its own config, or the source changed and was never applied. Look at each file's diff and decide which side is right; ask the owner when the intent is not clear from the diff. Take a home-side change into the source with `chezmoi re-add` on a branch and deliver it as above. Discard it by applying the source version once the source is merged. A tool that keeps rewriting a file means that file belongs out of chezmoi or behind a local include.

Update the relevant user-level instructions when directory layout, configuration sources, or tool entry points change.
